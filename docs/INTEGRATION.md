## 반영한 화면

1. 모바일 홈: 로고·메뉴·목적지 검색·세 가지 주차 상태의 목적지 카드.
2. 검색: 검색어 수정·삭제, 목적지 지도·검색 결과. 주차 시설과 목적지를 혼동하지 않도록 목적지 선택 단계를 명시.
3. 목적지: 주차 가능 여부 요약, 목적지·주차장 핀, 연결·대체 주차장 목록.
4. 주차장 상세: 사진/사진 없음, 혜택·요금·시간, 운영시간 경고, 위치·입구 정확도, 주차 등록·정산, 확인 시점, 하단 길안내.
5. 도보 안내: 출발·도착 위치, 등록된 도보 시간·단계. 미제공 거리와 경로선은 추정하지 않음.
6. 서비스 소개와 등록 준비 안내.

검색어는 목록 → 상세 → 도보 → 돌아가기에서도 URL 쿼리로 유지한다.

## 계약 처리

`GET /places`, `GET /places/{placeId}/parking`의 경로·필드·문자열 ID·null 규칙을 유지했다.
화면 이동 시 요청을 중단하며 이전 목적지 데이터가 새 화면에 노출되지 않게 요청 키를 검사한다.
HTTP 요청은 10초 후 중단하고 재시도 화면을 표시한다.
Zod 스키마로 잘못된 좌표·타입·날짜·사진 URL을 거부하고, 서버 내부 오류 메시지를 그대로 노출하지 않는다.
예시 데이터는 목 모드뿐 아니라 실제 백엔드의 `isDemo: true` 응답에서도 외부 길안내를 차단한다.

## 백엔드와 추가 합의할 것

### 입구 좌표 정확도 — 우선

v1의 `entranceCoordinates`는 공공데이터에서 대표 좌표로 대체될 수 있다.
실제 구현 `PlaceService.toLotDto`에서도 확인했다.

선택 필드 제안:

```ts
coordinateType?: 'entrance' | 'representative' | 'unknown';
```

프론트는 이 필드를 이미 선택적으로 수용한다. 없으면 `unknown`으로 취급해 입구 미확인으로 표시한다.
`entrance`만 확인된 입구로 표시한다. 미확인 좌표로 길안내할 때는 선택 모달에 주의 안내를 표시한다.
좌표가 없는 시설은 현재 백엔드 계약상 응답에서 제외된다.

### 배포 서버

공개 HTTPS API 주소가 필요하다. Netlify 프론트 출처를 서버 CORS에 추가해야 한다.
개발 프록시는 CORS 문제를 피할 수 있으나 정적 배포에는 적용되지 않는다.

### 아직 없는 기능

- 실제 입구 사진 저장·업로드, 목적지·주차 정보 등록·수정.
- 정확도 피드백 POST API.
- 등록되지 않은 일반 매장을 찾는 외부 장소 검색.
- 실제 보행 경로선·거리. 도보 시간은 서버 등록값만 표시.
- 방문 예정 시각에 따라 계산하는 운영시간 경고. 현재는 등록 문구 표시.

- 내비 앱 선택·기기 내 저장·체험 모드 외부 길안내 차단 확인.
- 주차 불가·미확인·빈 검색·없는 목적지와 서버 중단 시 오류, 서버 복구 후 재시도 확인.
- 360/390/430px 모바일 뷰포트에서 대표 화면의 가로 넘침 없음 확인.
- 지도 좌표는 실제 입구 정확도를 검증한 것이 아니며, 실제 iOS·Android 내비 실행 검증은 남아 있음.
